# Security Policy

## Supported Versions

Security fixes are handled on the default branch until the project publishes
versioned release support.

## Reporting a Vulnerability

Please do not open a public issue for a suspected security vulnerability.

Use GitHub private vulnerability reporting if it is enabled for the repository,
or contact the maintainer privately. Include:

- A short description of the issue.
- Steps to reproduce, if available.
- The affected version or commit.
- Any relevant logs or proof of concept.

The maintainer will acknowledge the report and coordinate a fix when the issue
is confirmed. If no private reporting channel is available, open a public issue
without exploit details and ask for a private contact path.
